# USB-заряд двух половинок ZMK через донгл

Этот документ описывает переносимую часть доработки ZMK. Она добавляет к USB-клавиатуре отдельный HID-интерфейс, через который компьютер запрашивает заряд **двух периферийных половинок**. Исходники примера: [`src/usb_split_battery.c`](../src/usb_split_battery.c), [`Kconfig`](../Kconfig), [`CMakeLists.txt`](../CMakeLists.txt).

## Требования

- Донгл является `ZMK_SPLIT_ROLE_CENTRAL`, обе половинки — BLE-периферийные устройства.
- Донгл имеет USB и `CONFIG_ZMK_SPLIT_BLE_CENTRAL_PERIPHERALS=2`.
- На половинках включены `CONFIG_BT_BAS=y` и `CONFIG_ZMK_BATTERY_REPORTING=y`.
- На донгле включено `CONFIG_ZMK_SPLIT_BLE_CENTRAL_BATTERY_LEVEL_FETCHING=y`.
- Пример написан для версии ZMK `v0.2`, закреплённой в [`config/west.yml`](../config/west.yml). При переносе на другую версию проверьте сигнатуры Zephyr USB HID API и приоритеты инициализации.

## Изменения в ZMK-конфиге

1. Скопируйте `src/usb_split_battery.c` в ваш конфиг, зарегистрированный как Zephyr-модуль. Если модуль уже есть, добавьте в его `CMakeLists.txt` строку `zephyr_library_sources_ifdef(CONFIG_ZMK_USB_SPLIT_BATTERY src/usb_split_battery.c)` внутри блока `zephyr_library()`.
2. Добавьте в `Kconfig` опцию `ZMK_USB_SPLIT_BATTERY` из этого репозитория. Она зависит от USB, роли central и получения уровня заряда периферийных устройств.
3. В `.conf` **только донгла** добавьте:

   ```conf
   CONFIG_ZMK_SPLIT_BLE_CENTRAL_BATTERY_LEVEL_FETCHING=y
   CONFIG_USB_HID_DEVICE_COUNT=2
   CONFIG_ZMK_USB_SPLIT_BATTERY=y
   ```

4. Убедитесь, что Zephyr-модуль подключён к сборке через `zephyr/module.yml` и `ZMK_EXTRA_MODULES` либо другой штатный способ вашего репозитория. В этом репозитории модуль уже зарегистрирован. Существующий [`build.yaml`](../build.yaml) собирает донгл через GitHub Actions, а [`workflow`](../.github/workflows/build.yml) использует ZMK v0.2. Дополнительная строка в `build.yaml` не нужна.
5. Отправьте изменения в свой GitHub-репозиторий и дождитесь завершения Actions. В логах задачи донгла проверьте, что в Kconfig появились `CONFIG_ZMK_USB_SPLIT_BATTERY=y` и `CONFIG_USB_HID_DEVICE_COUNT=2`. Скачайте UF2-артефакт для `lapka_wellum36_dongle` и перепрошейте **донгл**. Сброс настроек и новая прошивка половинок для этой функции не требуются.

## USB-протокол

Донгл создаёт дополнительный HID-интерфейс с Usage Page `0xFF00`, Usage `0x01`, Input Report ID `0x04`. Запрос `GET_REPORT(Input, ID 0x04)` возвращает три байта:

| Байт | Содержимое |
| --- | --- |
| 0 | `0x04` — ID отчёта |
| 1 | Заряд слота 0: 0–100%, `0xFF` — нет данных |
| 2 | Заряд слота 1: 0–100%, `0xFF` — нет данных |

Проценты берутся из кеша ZMK через `zmk_split_get_peripheral_battery_level`. Эта функция возвращает ошибку для отключённой половинки, поэтому `0%` остаётся допустимым уровнем заряда. Номера слотов определяются порядком сопряжения с донглом; при необходимости поменяйте подписи слева/справа в приложении Mac.

Интерфейс отвечает только на запрос чтения. Клавиши продолжает передавать штатный USB HID-интерфейс ZMK. В пример не добавлены сеть, хранение данных или запись команд в донгл.

## Проверка на устройстве

После прошивки подключите донгл к Mac, запустите приложение и убедитесь, что обе половинки показывают значения от 0 до 100. Выключите каждую половинку по очереди: вместо её значения должно появиться тире. Если подписи перепутаны, включите «Поменять половинки местами» в меню приложения. Если приложение показывает два тире, проверьте, что скачан именно новый артефакт донгла и что обе половинки соединены с ним.
